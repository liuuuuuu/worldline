# ADR-0003 · 地图贴图程序化生成，不用现成图片素材

- **状态**：已采纳
- **日期**：2026-10-07
- **决策者**：Alex / Ace

## 背景

P2 要给地球仪做一层「印刷纸质地图」的皮肤：纸面底色、陆地填色、墨线海岸线、经纬网、纸纹噪点。

常规做法是找一张等距圆柱投影的世界地图图片当贴图。问题：

1. **版权。** 大部分好看的复古世界地图都有版权或来源不明。这个项目要长期维护、公开分发（MIT），不能埋这种雷。
2. **风格锁定。** 一旦用图片，调色、对比度、经纬网密度就都改不动了——而 `docs/VISUAL.md` 明确要求「暖、哑光、低饱和」，并且视觉风格在 P5 之前会反复迭代。
3. **坐标不一致。** 图片贴图和 P3 的图钉定位是两套坐标系，容易错位。

## 决策

**用 Natural Earth 公有领域矢量数据（TopoJSON）在运行时绘制到 canvas，生成贴图。**

- 数据源：`world-atlas` 包的 `land-50m.json`（Natural Earth，公有领域）
- 解码：`topojson-client` 的 `feature()`
- 投影：等距圆柱（plate carrée）——这正是 `SphereGeometry` 的 UV 映射，所以经纬度到像素是纯线性映射，图钉定位（P3）可以复用同一套函数，不可能错位
- 绘制：`src/scene/paperTexture.ts`

## 考虑过的选项

| 选项 | 结论 |
|---|---|
| 找一张公有领域的世界地图图片 | 版权干净的可选项很少，且风格完全锁死 |
| Sentinel-2 无云影像（s2maps.eu） | **仅 CC BY-NC-SA，非商用** —— 原型可以，产品不行 |
| NASA Blue Marble 卫星影像 | 公有领域，但它是**照片**不是**印刷地图**，与「实体地球仪」的隐喻冲突 |
| **Natural Earth 矢量 + 运行时绘制** | ✅ 采纳 |

## 后果

**正面**
- 零版权风险
- 调色板、经纬网密度、线宽、纸纹全部是参数，改一行就能重调
- 同一份经纬度数据同时驱动贴图和图钉，坐标系天然一致
- 数据以静态资源按需加载（545 KB → gzip 179 KB），不进 JS bundle

**负面**
- 首次进入场景多一次本地 fetch + 一次 4096×2048 的 canvas 绘制（实测几百毫秒）
- 需要维护投影和绘制代码（约 250 行 + 156 个测试里的 30 个）

**缓解**
- 贴图分两段生成：先用空多边形画一张「纯纸面」贴图立即上屏，陆地数据到了再换——所以用户不会看到空白
- 数据加载失败时清空缓存允许重试，而不是把失败永久缓存

## 实测调参记录

第一次渲染暴露了两个只有看画面才能发现的问题：

1. **陆海对比几乎为零。** 初始调色板（纸面 `#ece2d0` / 陆地 `#d6c8ad`）在 ACES tone mapping 加主光之后被压平，大陆只能靠海岸线墨迹读出来。改成纸面 `#e2d6be` / 陆地 `#c6b28c`，拉开明确差值。
2. **经纬网完全不可见。** 线宽设为 1px，但可见半球只用到 4096px 贴图的约四分之一，1px 落到屏幕上不到一个像素，被 mipmap 平均掉了。改成 3px 并提高不透明度。

这两条都写进了代码注释——它们是**参数背后的理由**，不是随手填的数字。
